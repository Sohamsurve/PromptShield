Format: date · decision · reason.

## 2026-10-13

- **Public console:** The content-security policy allows the API host taken from `NEXT_PUBLIC_API_BASE` or `INTERNAL_API_URL` at build time, including the matching `wss` origin for the live event socket. Localhost stays allowed. Reason: the socket connects straight to the API, and the Render hostname is only known when the console is deployed.

## 2026-10-11

- **Submission deck:** The pitch deck maps each architecture step to a demo the prototype is allowed to show, and states the AI pieces as signatures, a small local classifier, and a gray-zone judge. Business impact stays on the path in front of the model. No market figure is added. Reason: the submission asks the architecture to support the working demo, and the measured claim is still F1 / D1 provisional.
- **Caller sign-in:** `/login` and `/signup` use the same white neo-brutal theme as the landing page, including the theme switch. Admin sign-in stays on the dark shell. Reason: those two screens are part of the public site, and a forced dark card did not match the landing.
- **Product README:** `README.md` is the reviewer page: concept, how a scan works, measured performance, use cases, and advantages. The build specification moved to `docs/BUILD_SPEC.md` with the same section numbers. Reason: the GitHub page was opening as agent instructions, and a judge should see the product first.
- **Submission README:** The GitHub README opens with the product, the F1/D1 provisional declaration, the golden-suite numbers, and the demo commands. The build specification stays underneath. Reason: a judge who stops in the first screen should see the measured position, and coding agents still have §0 and §11.
- **Caller landing:** `/` explains the concept, the three ways to use it, the five verdicts, and the advantages. It does not quote recall or false-positive numbers. Reason: the first screen a caller sees should say what the firewall is for, and the measured scores stay in the eval reports.
- **Caller playground:** Signed-in callers open Arena, Coverage, and Red team at `/portal/arena`, `/portal/coverage`, and `/portal/redteam`. `POST /v1/demo/run` and `POST /v1/policy/test` are allowed for a caller, and those scans are stored on the account. Policy writes, `POST /v1/eval/run`, and the regression queue stay admin-only. Reason: callers should try the same gallery and playground as the admin site, without changing the firewall.
- **Caller keys:** A signed-in caller creates and revokes keys at `/portal/keys` (`/v1/me/keys`). The role is always `user`. Scans made with an extra key are stored on the account key, so the dashboard lists them together. The key created at sign-up is marked `primary` and cannot be revoked. Reason: callers need their own keys the way other API apps do, without access to the admin key list.
- **Test packs:** External attack packs live under `fixtures/corpora/` (`adversarial`, `agentic`, `whitetext`, `white_text`). Reason: the repo root should match the layout in README §3.1.
- **Prototype claims:** The submission pack quotes the golden report from 2026-10-10 (acted 0.6122, type 0.4778, benign FPR 0/500) and states F1/D1 provisional. The v2.0-rc2 curve stays as prior context. Reason: a judge should not read the older pack as the current result, and the unmet recall targets stay unmet.
- **Admin users:** `GET /v1/accounts` is admin-only and lists each account’s name, email, active keys, and scan counts by verdict. Passwords and key hashes stay out of the response. Reason: admin control needs usage without opening the caller’s secrets.
- **Safe alternative:** `block` and `quarantine` responses include `safe_alternative`. It is the redacted text with the removal marker stripped when that remainder is long enough and does not still carry an override phrase. Canary tokens and a leftover “low-contrast adversarial text” caption are removed before that check. Otherwise it is the fixed line “Please rephrase this as an ordinary request.” Allow and sanitize do not set it. Reason: a blocked call should offer a harmless next step, and that line must not repeat the attack or a canary that sat beside the hidden instruction.
- **Account sign-in:** Callers create an account with name, email, and a password of at least 8 characters. The password is stored as a PBKDF2 hash. Sign-up returns that account's API key once. Sign-in checks the password and returns a separate session token for the same key, so scans stay on the account. Admin sign-in at `/admin` is unchanged. Reason: the caller screen should be a normal sign-in and sign-up, and the API key should still be the credential other apps send.

## 2026-10-10

- **Owner sign-in:** The first screen is the public landing page. The owner console is a separate set of screens behind a fixed owner sign-in. In demo mode that sign-in is the canary password `promptshield-owner` unless `PROMPTSHIELD_OWNER_PASSWORD` is set. The owner can also create more admin keys. The password is not returned by the API. Reason: callers and the owner should not share one open console.
- **Caller keys:** The owner creates a bearer key from `/keys`. The plaintext is returned once and only a hash is stored. A caller key can scan and list its own scans. It cannot create keys, change policy, or read another caller's scan. A presented key that is unknown or revoked is rejected even while demo mode is on. A call with no key stays open in demo mode. `PROMPTSHIELD_API_KEY` stays the owner credential when `DEMO_MODE=0`. Reason: one service, with a user view and an owner view, instead of a single shared secret.
- **Service key:** Scan and guard POSTs require `authorization: Bearer` or `x-api-key` when `DEMO_MODE=0`. The key is `PROMPTSHIELD_API_KEY`. Health reports whether a key is configured and never returns the value. Demo mode stays open so the local console keeps working. Reason: other agents should call the same `/v1/scan` service, not a separate endpoint per framework.
- **One firewall API:** Removed the OpenAI, LangGraph, and NeMo-shaped routes. Every agent calls `POST /v1/scan`, `POST /v1/scan/file`, and the guard endpoints, then uses its own model. Reason: those three routes repeated the same scan.
- **Broader phrase rules:** Added tool-to-`evil.test`, secret-file exfil, policy-replacement, loaded-preamble, memory-write, and jailbreak-persona rules. Each has a benign counter-example. Golden safe FPR stayed 0.0 and offline eval-fast FPR stayed 0.0. Acted recall moved from 0.4967 to 0.6122; type recall from 0.32 to 0.4778; predictability stayed 1.0. Reason: those phrases are attacks even when they are short. Educational quotes that already fail quotation detection can match the same sentence.
- **Oversized classifier span:** If a classifier hit is at or above `clf_graded.quarantine` (0.92) but the span is too large to redact, the decision is quarantine. The grades were not lowered. A score under 0.92 still allows. Reason: the old path treated that span as localised, refused the redaction, then allowed. Golden safe FPR stayed 0.0; offline `eval-fast` FPR stayed 0.0. Frozen acted recall moved from 0.4867 to 0.4967.
- **Golden suite v1:** `eval/golden/` is the frozen predictability set: 100 cases for each of the 9 attack types and 50 safe cases. `manifest.json` hashes the files. `make golden` scores acted recall, type recall, benign false-positive rate, scan-to-scan predictability, and latency with the judge off and the shipped policy template. It is not training data, and a low recall does not fail the command. A predictability miss exits 2. First run at `46d3c98`: acted recall **0.4867**, type recall **0.32**, benign FPR **0.0**, predictability **1.0**, latency p50 **10.2 ms** / p95 **14.3 ms**. Reason: one stable ruler for progress, kept off the tuning sets.
- **Golden suite v2:** Each attack type now also has 50 safe cases (`control_for`), plus the original 50 ordinary documents (1,400 rows). v1 history is not comparable. Rescore at `46d3c98`: acted recall **0.4867**, type recall **0.32**, safe FPR **0.0** on all 500, predictability **1.0**. Reason: false alarms need a safe set per family, not one shared pile.
- **PromptShield_Golden_Suite_v1:** Moved under `eval/golden/sources/`. Only the distinct sentences (not the per-format copies), the 22 PNGs, and the PDF/DOCX/XLSX/PPTX packs are scored, as `cases/imported_ps_v1.jsonl`. They do not change the 100+50 counts. First imported score: acted **0.180** (46/256), type **0.117**, safe FPR **0/32**. The four Office/PDF packs were allow. Reason: 988 of 1,250 rows repeat one sentence; scoring those copies would pretend the suite is larger than it is.
- **shadcn tokens:** UI components use the lab palette (`--paper`, `--ink`, `--uv`, verdict colours) through the shadcn variable names. No zinc defaults. Reason: README §9.
